# 시작하기

프로젝트에서 실제 스킬 이름 `game-design-for-immersion`을 호출하고, 알고 싶은 개념이나 현재 해결할 문제를 붙입니다. 설치 방법은 [README](../README.md#installation)에 있습니다.

[README](../README.md) · [가이드 홈](index.md) · [작업 흐름](workflow.md) · [고급 활용](advanced-usage.md) · [문제 해결](troubleshooting.md) · [릴리스 가이드](../release/README.md)

## 이 문서에서 할 일

1. 첫 학습 또는 첫 설계 요청을 복사해 현재 상황으로 바꿉니다.
2. 장 번호를 모르면 자료 선택 표로 시작합니다.
3. 결과에서 근거·확정 정책·미정 선택지를 구분했는지 확인합니다.

## 첫 학습 요청

```text
$game-design-for-immersion 원서 1.1절의 RLD를 설명해줘.
발견·거리 인식·도달 시간 예측·입력 실패의 차이를 새 러닝 액션 예시로 보여줘.
책의 설명과 새 예시를 구분하고, 관련 자료와 본문 쪽을 적어줘.
마지막에 이해 확인 문제 2개만 내고 정답은 내가 답한 뒤 알려줘.
```

관련 파일을 읽었는지, 결과 통과율과 행동 원인을 구분하는지 확인합니다. 적은 쪽이 절 전체 범위가 아니라 문장 단위인지는 [공통 산출물 검수](advanced-usage.md#review-criteria)의 ‘인용 쪽’ 항목으로 봅니다. 이해 확인 문제 수는 요청량이며 책의 규격이 아닙니다.

## 첫 설계 요청

가상 입력을 현재 프로젝트의 정보로 바꿉니다.

```text
$game-design-for-immersion 3분 협력 보스 스테이지의 경험을 설계해줘.
목표: 서로의 도움이 마지막 돌파를 만들었다고 느끼기.
확정: 보스 체력과 보상은 유지, 전투력 판매 없음.
미정: 역할 분담과 실패 뒤 재시도 위치.
난이도·공통 경험·감정 곡선의 관련 자료를 먼저 읽어줘.
산출물: 구간별 행동·감정·상호 기여, 역할 대안, 검증할 플레이테스트 항목.
책의 근거와 새 제안을 구분하고 미정 정책을 확정하지 마.
```

첫 결과에서는 모든 수치가 채워지는지보다 목표와 행동, 도움과 결과, 실패와 복귀가 연결되는지 봅니다.

## 장 번호를 모를 때 <a id="find-materials"></a>

| 문제 | 중심 장·상세 절 | 함께 읽을 자료 |
|---|---|---|
| 장애물을 못 보거나 점프가 늦다 | 1장 / 1.1(s01) | RLD·실패 원인 |
| 공격만 선택하고 전략이 없다 | 1장 / 1.2(s02) | 선택·상성·후속 대응 |
| 친구 기능은 있지만 교류가 없다 | 2장 / 2.2–2.3(s04–s05) | 4.4(s14)의 호혜 |
| 계속 긴장시켜 피로하다 | 3장 / 3.1–3.3(s06–s08) | 실패·중단·복귀 |
| 성장 수치는 늘지만 체감이 없다 | 4장 / 4.1(s11) | 3.4(s09)·4.3(s13) |
| 귀속·유통·경제를 비교한다 | 4장 / 4.4–4.8(s14–s18) | 가치·수요·확정 수익 모델 |

```text
$game-design-for-immersion 성장 시스템은 6개인데 강해지는 느낌이 약해.
참조 색인에서 먼저 읽을 장과 상세 절을 고르고 선택 이유를 설명해줘.
실제 성장 데이터는 아직 없으니 원인을 단정하지 말고 필요한 입력과 검토 기준을 정리해줘.
```

## 결과 확인과 후속 요청

책의 근거, 실제 읽은 파일, 확정 정책, 미정 선택지, 새 가정이 구분되었는지 확인합니다. 다음 요청에서는 선택한 결과를 지정합니다.

```text
방금 역할 대안 중 공동 방어안을 선택했어.
보스 체력과 보상은 유지하고, 방어 실패 때의 감정 흐름과 복귀만 보완해줘.
재시도 위치는 미정으로 유지하고 각 선택의 영향과 검증 항목을 적어줘.
```

새 대화에서는 기존 결과를 붙이거나 문서 경로를 제공합니다. 더 자세한 요청은 [18절별 고급 활용](advanced-usage.md)을, 확인 기준은 [검수 가이드](validation.md)를 참고합니다.
