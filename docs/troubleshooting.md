## 스킬 이름이 보이지 않음

현재 프로젝트와 [SKILL.md](../.agents/skills/game-design-for-immersion/SKILL.md)의 호출 이름을 확인합니다. `game-design-for-immersion` 폴더 전체가 해당 호스트 경로에 있어야 합니다. 새로 설치했다면 새 세션에서 확인합니다. Codex 목록 발견과 실제 자료 읽기는 따로 확인합니다.

## Claude Code 별칭이 끊어짐

프로젝트 루트에서 `.claude/skills/game-design-for-immersion`이 `../../.agents/skills/game-design-for-immersion`을 가리키는지 확인합니다. 같은 경로에 파일·폴더·다른 링크가 있으면 자동으로 덮어쓰지 않습니다. README의 설치 명령은 기존 대상을 보존합니다.

## 개인 설치가 다른 버전임

현재 개인 링크는 이 프로젝트의 정본을 가리킵니다. 프로젝트 이동·삭제 뒤에는 링크 대상과 실제 `SKILL.md` 바이트를 확인합니다. 다른 프로젝트로 복사한 독립 설치는 자동 동기화되지 않습니다. 배포할 때 전체 폴더를 같은 버전으로 옮깁니다.

## 장 번호가 기대와 다름

원서 실제 장은 4개입니다. `ch01`–`ch04`는 원서 장, `s01`–`s18`은 상세 참조입니다. 초기 `ch07`은 현재 `s07`, 원서 3.2절 감정 곡선입니다. [목차 대응](../.agents/skills/game-design-for-immersion/references/coverage.md)에서 원서 번호와 파일을 확인합니다.

## 자연어 요청으로 스킬이 불리지 않음 <a id="direct-invocation"></a>

스킬 설명만 보고 자동으로 고르는 방식은 호스트, 함께 설치된 스킬 수, 요청 표현에 따라 달라집니다. 답이 책과 무관한 일반론이면 스킬을 직접 지정합니다.

| 호스트 | 직접 호출 예시 |
|---|---|
| Codex | `$game-design-for-immersion 원서 3장으로 감정 곡선을 검토해줘.` |
| Claude Code | `/game-design-for-immersion 원서 3장으로 감정 곡선을 검토해줘.` 또는 `game-design-for-immersion 스킬을 사용해서 원서 3장으로 감정 곡선을 검토해줘.` |
| Antigravity | `game-design-for-immersion 스킬을 사용해서 원서 3장으로 감정 곡선을 검토해줘.` (설치 버전이 slash 호출을 지원하면 slash도 가능) |

## 답변이 일반론이거나 관련 자료를 안 읽음

아래 예시는 Codex 형식입니다. 다른 호스트에서는 첫 줄을 [직접 호출](#direct-invocation) 형식으로 바꿉니다.

```text
$game-design-for-immersion 참조 색인에서 이 문제의 자료를 고른 뒤
선택한 자료를 검색 결과 몇 줄이 아니라 해당 절 전체로 읽고 답변을 다시 작성해줘.
전체 관점이나 상세 조건이 더 필요하면 관련 장 또는 다른 절을 보충해줘.
읽은 파일·원서 절·쪽 근거를 적고, 자료에 없는 내용은 새 제안으로 구분해줘.
```

색인은 상세 내용의 대체 자료가 아닙니다. 요청 범위가 넓으면 한 기능·한 세션·한 결정으로 좁히고 목표·확정/미정 조건을 제공합니다.

## 쪽 인용이 절 전체 범위이거나 원문 파일을 찾으려 함 <a id="citations"></a>

스킬 자료의 문장 끝에 붙은 `(본문 N쪽/PDF M쪽)`이 인용 위치입니다. 파일 머리의 ‘목차 탐색 범위’는 자료를 찾는 범위라서 인용 근거가 아닙니다. 답변이 “본문 2–47쪽”처럼 절 전체 범위를 근거로 들거나 프로젝트에서 원문 PDF를 찾으려 하면 다음처럼 다시 요청합니다.

```text
game-design-for-immersion 스킬 자료만 근거로 다시 답해줘. 원문 파일은 찾지 마.
선택한 파일은 해당 절 전체를 읽어줘.
책의 서술에는 자료에 적힌 문장 단위 쪽을 붙이고, 스킬의 정리와 새 제안은 그렇다고 표시해줘.
```

## 원문과 직접 대조하고 싶음 <a id="source-check"></a>

원문 PDF는 스킬에 들어 있지 않습니다. 원문과 직접 대조하려면 사용 권한이 있는 원문 파일의 위치와 확인할 쪽을 함께 알려 줍니다. 쪽을 모르면 먼저 스킬에 확인할 쪽을 물어봅니다.

```text
game-design-for-immersion 스킬로 표 4.1 설명을 원문과 대조해줘.
원문: /absolute/path/몰입을 설계하는 게임 기획.pdf, 확인할 쪽: 본문 232쪽(PDF 248쪽)
스킬 자료의 서술과 원문이 다른 부분만 쪽과 함께 알려줘. 원문 문장은 길게 옮기지 마.
```

## 미정 정책이나 수치가 확정됨

원래 입력을 다시 제시하고 확정·미정·가설을 구분하도록 요청합니다. 책 사례의 과금·진행 일수는 현재 프로젝트의 정책이 아닙니다. 외형만 유료로 확정했다면 전투력 판매 제안과 충돌하는지 확인합니다.

## 성장 계산이 맞지 않음

표 4.1의 반복 주기와 첫 추가 상승, 표 4.10의 도달 레벨과 누적 상승, 표 4.11의 능력/비용 비중을 나눠 확인합니다. 6·30레벨처럼 여러 곡선이 겹치는 레벨은 오류로 단정하지 말고, 시작 레벨을 달리해 중복을 막은 것인지 의도적으로 겹친 것인지 구분해 요청합니다. 산식·단위·검산 결과를 요청하고 [수치 참조](../.agents/skills/game-design-for-immersion/references/figures-and-formulas.md)를 읽습니다. 원본 표가 필요하면 [원문 대조 요청](#source-check)을 사용합니다.

## 수식·표·그림을 정확히 확인할 수 없음

OCR의 글자·기호·열 정렬 문제와 원문 자체의 모호함을 구분합니다. 원문 PDF가 있으면 [원문 대조 요청](#source-check)으로 해당 쪽을 확인하고, 여전히 불명확하면 위치와 한계를 남깁니다. 확인되지 않은 식·VIP 행·결손 값을 추정해서 완전한 원문 표로 제시하지 않습니다.

## 검사가 통과했는데 실제 호출이 안 됨

정적 검사는 앱 발견·인증·실제 호출을 보증하지 않습니다. 사용 호스트의 원래 로그·종료 코드·읽기 경로·해시를 확인합니다. 재시험할 때는 새로운 기록을 남기고 이전 실패 기록을 덮지 않습니다. 범위와 복구 방법은 [검수 가이드](validation.md#evidence-levels)를 읽습니다.

## 검사 도구가 없음

기본 스킬 사용에는 변환기·Python 패키지가 필요하지 않습니다. 제작 검사를 하려면 Python 3.11 이상, PyYAML·markdown-it-py, 원문 대조용 PDF 추출·렌더 도구를 확인합니다. 도구 부재와 내용 오류를 구분해 기록합니다.
