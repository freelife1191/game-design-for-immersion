## 개념 학습 <a id="learning"></a>

개념의 범위에 맞는 자료를 선택해 읽고 **개념 → 적용 조건 → 책 사례 → 새 예시 → 이해 확인** 순으로 요청합니다. 전체 관점이 필요하면 장 자료를, 특정 기법·조건이면 상세 절을 먼저 읽습니다. 저자의 관점과 현재 프로젝트의 사실을 구분합니다.

```text
$game-design-for-immersion 원서 3.3절의 가벼움/무거움과 느림/빠름을 설명해줘.
난이도와 템포를 다른 축으로 비교하고 각 조합에 새 예시를 하나씩 붙여줘.
30분 같은 예시 시간을 모든 게임의 필수 규격으로 쓰지 마.
```

## 새 경험 설계 <a id="design"></a>

| 단계 | 결정할 것 | 산출물·다음 입력 |
|---|---|---|
| 목표 경험 | 대상·시간 단위·기억할 순간 | 목표문·확정/미정 조건 |
| 핵심 행동 | 조작 병목·실질적 선택·상호 기여 | 행동/선택 표 |
| 경험 변화 | 고조·회복·기조·중단과 복귀 | 타임라인·곡선 선택 이유 |
| 성장과 보상 | 새 행동·해금·증가량·수요 | 성장/보상 대응표 |
| 경제 조건 | 수익 모델·유통·소비·생산 | 같은 조건의 대안표·단위 |
| 검증 계획 | 관측 항목·반례·결정 조건 | 플레이테스트 계획 |

순서대로 모든 표를 채우는 것이 목적은 아닙니다. 짧은 퍼즐이라면 경험 변화와 실패·복귀만, 경제 개선이라면 수요와 생산·소비부터 좁힙니다. 원서 사례 숫자는 프로젝트 가정과 별도 열에 둡니다.

## 기존 기획 검토 <a id="review"></a>

자료를 제공하고 **문제 문장 → 관련 근거 → 플레이 영향 → 최소 수정안 → 필요한 결정**을 요청합니다. 실제 관측 자료가 없으면 원인을 가설로 둡니다.

```text
$game-design-for-immersion 아래 메모를 검토해줘. 파일은 수정하지 마.
“초보도 계속 긴장해야 한다. 실패하면 처음부터 3분 연출을 반복한다.
매일 같은 보상을 지급하면 매번 큰 절정이 생긴다.”
확정: 세션 3분. 미정: 재시도 지점과 보상 노출 방식.
관련 장·절을 읽고 문장별 근거, 영향, 수정안, 확인할 정책을 표로 정리해줘.
```

## 비교와 반복 보완

대안은 목표·대상·보상·시간·확정 정책을 동일하게 두고 바꾸는 변수만 지정합니다. 선택한 결과에 다음 요청을 연결하고 변경 영향이 있는 표·정책만 다시 봅니다.

```text
방금 파동형안을 선택했어. 마지막 협력 돌파는 유지해줘.
재시도 연출을 줄이면 긴장·회복·보상 기대에 어떤 영향이 있는지 검토해줘.
새 시간 값은 가설로 표시하고 플레이테스트 질문과 실패 반례를 적어줘.
```

## 산출물 확인

학습 답변은 조건과 개념을, 설계 답변은 행동과 결과를, 검토 답변은 문장 근거와 영향을 확인합니다. “재미있다”, “리텐션이 오른다” 같은 결론에는 관측 근거가 필요합니다. 계획한 QA 시나리오와 실행한 테스트 결과는 구분합니다. 자세한 기준은 [검수와 테스트](validation.md)와 [고급 활용](advanced-usage.md#review-criteria)에 있습니다.
