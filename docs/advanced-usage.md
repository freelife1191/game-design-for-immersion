## 요청문 작성과 자료 선택

Codex에서는 `$game-design-for-immersion`, Claude Code에서는 `/game-design-for-immersion`으로 시작합니다. Antigravity에서는 스킬 이름을 포함한 자연어 요청을 사용할 수 있으며, slash 호출은 설치 버전의 지원 여부를 확인합니다. 원서 장은 `ch01`–`ch04`, 상세 자료는 `s01`–`s18`입니다.

특정 기법·조건은 상세 절에서 시작하고, 큰 설계 관점이 필요할 때 장 자료를 보충합니다. 원문 절 번호·용어·수치로 찾을 때는 [참조 색인](../.agents/skills/game-design-for-immersion/references/index.md), [전략 원서 절별 읽을 위치](../.agents/skills/game-design-for-immersion/references/sections/s02-cold-strategy.md), [심리 세부 기법 바로가기](../.agents/skills/game-design-for-immersion/references/sections/s04-psychology.md)를 이용합니다.

각 예시의 **가상 입력을 실제 프로젝트 정보로 바꾸고**, 유지할 확정 정책과 아직 선택하지 않은 정책을 나눕니다. 목표 시간·보상·현재값이 없다면 필요한 자료 목록이나 기호식부터 받습니다.

```text
$game-design-for-immersion [현재 문제]를 [진단/설계/비교/검토]해줘.
맥락: [장르·대상 플레이어·콘텐츠 구간·현재 자료]
확정: [유지할 조건] / 미정: [아직 정하지 않은 변수]
읽을 자료: [관련 원서 절과 ch##/s##]
산출물: [결정에 필요한 표·초안·검토 결과와 열]
책의 설명·스킬 정리·새 제안을 구분하고, 읽은 자료와 문장 단위의 원서 쪽을 적어줘.
자료가 없는 수치는 미정으로 남기고 다음에 필요한 입력을 알려줘.
```

**정책을 읽는 기준:** 판매 대상·플레이 효과와 가격·혜택 조건을 나눕니다. 예를 들어 외형만 유료라는 정책은 성능·진행 우위 판매를 배제하지만, 아직 미정인 외형 가격·전시 등급·외형 전용 할인까지 자동 금지하지는 않습니다.

**근거를 읽는 기준:** 각 절의 ‘원문 탐색 범위’는 자료를 찾는 범위이며 인용 쪽이 아닙니다. 인용 쪽과 저자·스킬 정리의 구분은 [공통 산출물 검수](#review-criteria)의 ‘인용 쪽’ 항목으로 확인합니다.

**결과를 이어갈 때:** 같은 대화에서는 선행 요청 ID와 선택한 안을 지정합니다. 새 대화에서는 **선택한 표·초안, 유지할 확정 정책, 미정 목록, 적용 조건·예외의 판정과 근거 위치**를 함께 제공합니다. “방금 결과를 보완해줘”만으로는 어떤 안을 고른 것인지 재현하기 어렵습니다.

## 보강한 조건·예외로 예시 찾기 <a id="refined-conditions"></a>

조건은 읽었다는 표시보다 **성립 여부·판단 근거·해당 없는 범위**로 산출물에 남기는 것이 중요합니다. 후속 요청에는 이 판정과 미확인 항목을 함께 전달합니다.

| 확인할 조건·예외 | 예시에서 실제로 할 판단 | 예시·후속 |
|---|---|---|
| 쾌감의 원천·극단 스탯 | 캐릭터/플레이어 경험과 실제 효율을 구분하고, 처치(생존) 턴이 같은지를 기준으로 턴·피해를 검산 | [보스 역산](#s01-b), [균형 반례](#s02-followup) |
| 숙련 부족·실제 능력 부족 | 두 유형을 나누고, 출현 빈도 조정은 능력 부족 쪽, 보상 스테이지는 두 유형 모두에 해당하는지 판정. 반복 시도로 줄어드는 실패는 따로 구분 | [장애물 실패 분해](#s01-a) → [단일 변수 후속](#s01-followup) |
| 제어 균형의 전제 | 상성·다중 목표는 저자의 첫째 관점(실력 비율)이라 성장 격차가 그 범위인지 판정하고, 보상 제한은 압도적인 플레이어·팀이 나올 때의 별도 조치라 따로 판정. 이미 들어간 수단 위에 새 수단을 더하는 템포 비용도 확인 | [역전·역할 비교](#s02-b) → [균형 반례](#s02-followup) |
| 비전투 전략·단기 미션 | 핵심 루프의 선택과 템포 비용을 비교 | [경영 예시](#common-05) → [미션 후속](#common-05-followup) |
| 분노·심리 용어·요청 순서 | 사건 유형의 성립 조건과 책/일반 용어의 범위를 분리 | [심리 조건 학습](#common-06) → [조건 변경 후속](#common-06-followup) |
| 슬픔·상실 뒤 행동 | 슬픔이 회피로 흐르는 경로와 결과를 거부·저항해 분노에 가까워지는 경로를 구분 | [동료 상실 검토](#s03-b) → [감정 부작용 후속](#s03-followup) |
| 동조·협력·제시 순서 | 공개 판단 시점·도움 여력·비교 관계(선택지 유형·비례)·정보 간격을 확인하고, 프레이밍은 이익 틀과 손실 틀의 방향, 사회적 태만 대응은 도전 난도의 제한까지 확인 | [협력 진단](#s04-a), [제시 비교](#s04-b) → [반례 후속](#s04-followup) |
| 사회 교류의 필요·공통 경험 수단 | 플레이어가 교류를 원하는지(저자는 일반인의 게임 목적이 휴식일 수 있다고 씀)를 입력으로 확인하고, 공통 경험은 협력을 먼저, 소통·교류 유도를 그다음에 설계 | [친구·채팅 진단](#s05-a) |
| 파동형 곡선 | 반복마다 관계·목표·숨은 서사의 변화가 있는지 확인하고, 변화 없는 반복은 반례로 남김 | [곡선 선택](#s07-a) |
| 장기 복귀·메인 복귀 표지 | 게임 속 실패 중단과 실생활로 떠난 중단을 나누고, 후자는 경험 유형을 먼저 본 뒤 중단 시간이 짧으면 바꾸지 않음. 길 때 조절 가능한 상태와 고정 콘텐츠를 분리하며 표지 개수는 강제하지 않음 | [복귀안 비교](#s07-b), [고정 퀘스트 복귀](#common-07) → [복귀 후속](#s07-followup), [배너 후속](#common-07-followup), [분기 후속](#s10-followup) |

| 핵심 스토리 지점의 선택권 | 저자가 선택권을 주지 않아야 한다고 쓴 핵심 지점을 지키고, 핵심이 아닌 분기의 선택지 설계와 구분 | [멀티 엔딩](#s10-b) → [분기 후속](#s10-followup) |

## 1.1 뜨거운 자극형 게임 <a id="section-01"></a>

**사용할 상황:** 장애물 앞에서 반복 실패하지만 무엇을 조정해야 할지 모르거나, 보스의 스킬 목록보다 플레이어의 대응 경험을 먼저 정하려 할 때 사용합니다.

**준비할 입력:** 실패한 구간의 영상·화면 속도·장애물 표시·입력 판정 자료를 준비합니다. 보스 설계에는 현재 공격 방식, 엄호가 필요한 순간, 유지할 유료 정책을 적습니다. 자료가 없으면 원인 가설과 추가 수집 항목부터 받습니다.

**읽을 자료:** [s01 — 뜨거운 자극형 게임](../.agents/skills/game-design-for-immersion/references/sections/s01-hot-challenge.md)과 [원서 1장](../.agents/skills/game-design-for-immersion/chapters/ch01-game-difficulty.md). 연계할 절은 3.2·3.3입니다. 원문 탐색 범위는 본문 2–47 / PDF 18–63입니다.

### A. 장애물 실패를 지각·예측·입력 문제로 나누기 <a id="s01-a"></a>

요청 ID: `s01-a`

**사용할 때:** 러닝 액션에서 초보가 장애물 앞에서 반복 실패한다. 영상과 행동 로그는 아직 없다.

**얻을 결과:** 실패 단계 / 원인 가설 / 확인할 영상·로그 / 바꿀 변수 / 유지할 변수의 진단표를 만듭니다. 자료가 없는 가설에는 미확인 표시를 붙입니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion
러닝 액션의 장애물 실패를 네 단계로 나눠 원인 가설을 세워줘.
가상 입력: 러닝 액션에서 초보가 장애물 앞에서 반복 실패한다. 영상과 행동 로그는 아직 없다.
확정: 화면 속도 유지. 미정: 시야·예고·발판 폭·입력 보정.
읽을 자료: 원서 1.1절(s01)을 실제 읽고, 전체 관점이 더 필요하면 1장(ch01)을 보충해줘.
산출물: 실패 단계 / 원인 가설 / 확인할 영상·로그 / 바꿀 변수 / 유지할 변수의 진단표를 만들어줘. 자료가 없는 가설에는 미확인 표시를 붙여줘.
책의 설명·사례 재구성·새 제안을 구분하고 실제 읽은 자료와 원서 쪽을 적어줘.
미정 정책은 선택지·영향·검증 질문으로 남기고, 자료가 없는 수치를 확정하지 마.
원인 가설을 숙련도가 부족한 유형과 실제 능력이 부족한 유형으로 나누고, 능력 부족 쪽에만 쓰는 출현 빈도 조정과 두 유형 모두에 쓸 수 있는 보상 스테이지가 이 입력에 해당하는지 판정해줘. 해당하지 않으면 이유를 적어줘.
저자는 경험이 쌓이면 시간 예측에 드는 계산이 짧아져 난이도 체감이 낮아진다고 쓰므로, 반복 시도로 줄어드는 실패와 변경 변수로 줄여야 하는 실패를 가설표에서 나눠줘. 저자가 경험만으로 깨는 중복 콘텐츠의 대응으로 든 불규칙한 속도 변화·감속 같은 외부 요인은 이 입력의 확정 정책(화면 속도 유지)과 맞는지 판정하고, 맞지 않으면 해당 없음으로 표시해줘. 점프 준비 동작을 꼭 넣어야 한다면 같은 조작에 보조 수단을 붙이는 저자의 대안(점프 버튼을 오래 누를수록 높이 뛰기)을 입력 보정 후보로 비교해줘.
```

</details>

**확인할 점:** 화면 속도를 고정한 채 시야·예고·발판·판정 중 무엇을 시험할지 구분하고, 로그 없이 반응 속도 문제로 단정하지 않았는지 봅니다.

**보강 조건 확인:** 숙련도 부족과 실제 능력 부족을 나눕니다. 출현 빈도 조정은 능력이 부족한 유형, 보상 스테이지는 두 유형 모두에 적용되는 방향이며, 이 입력의 단일 장애물에 스테이지 단위 조정이 해당하는지 판정합니다. 경험이 쌓이며 줄어드는 실패와 속도 변화 같은 대응은 구분하며, 화면 속도 유지가 확정이므로 속도를 바꾸는 대응이 맞지 않으면 해당 없음으로 남깁니다.

### B. 회피·엄호 경험에서 보스 패턴 역산하기 <a id="s01-b"></a>

```text
회피와 엄호를 번갈아 수행하게 하는 협력 보스의 행동을 역산해줘.
가상 입력: 협력 보스에서 회피와 엄호를 번갈아 수행하는 경험을 만들고 싶다.
확정: 피해량이나 전투력 상승을 유료로 판매하지 않음. 미정: 역할 수·에너지 순환·실패 빈도.
읽을 자료: 원서 1.1절(s01)을 실제 읽고, 전체 관점이 더 필요하면 1장(ch01)을 보충해줘.
산출물: 플레이어 대응 / 보스의 신호·행동 / 필요한 역할 / 에너지 순환 / 단순 연습 / 복합 도전의 설계표를 만들어줘. 역할 수와 실패 빈도는 대안으로 남겨줘.
책의 설명·사례 재구성·새 제안을 구분하고 실제 읽은 자료와 원서 쪽을 적어줘.
미정 정책은 선택지·영향·검증 질문으로 남기고, 자료가 없는 수치를 확정하지 마.
목표 쾌감을 캐릭터가 더 강해지는 경험과 플레이어가 평소 능력을 넘는 경험으로 구분해줘. 보스의 위상·약화 과정과 실제 회피·엄호·처치 효율이 어떻게 연결되는지 적고, 연출만 화려해져 효율이 낮아지는 반례도 확인해줘. 역할 수를 비교할 때는 역할 구분이 지나치게 명확해 직업마다 난이도가 크게 달라지는 반례와, 보스 스킬이 특정 직업의 대응에만 몰려 다른 직업이 할 일이 없어지는 반례도 확인해줘. 에너지 순환은 저자가 마나만 쓰면 조작 방식의 다양화를 스킬 쿨타임에 의존해야 하고 새 에너지 시스템은 다양한 조작 방식을 설계하기 쉽지만 하나의 시스템만 고집하면 인지 비용이 오른다고 쓰며 핵심은 새 조작 방식이라고 하므로, 시스템 종류를 확정하지 말고 어떤 조작 방식을 만들려는 순환인지 적어줘.
```

</details>

**확인할 점:** 보스 기술마다 요구하는 회피·엄호 행동이 연결되어야 합니다. 새로운 역할 수나 에너지 수치가 이미 정해진 사양처럼 쓰이지 않았는지 확인합니다. 에너지 시스템을 고르는 이유가 새 조작 방식인지도 봅니다.

**보강 조건 확인:** 캐릭터의 강해짐과 플레이어 능력 초월을 구분하고, 연출의 강도와 실제 회피·엄호·처치 효율을 따로 확인합니다. 역할 구분이 지나치게 명확할 때의 직업 간 난이도 격차와 보스 스킬 빈도의 쏠림도 반례로 둡니다.

### B. 성장 격차 속에서도 역전·역할이 남는 안 비교하기 <a id="s02-b"></a>

요청 ID: `s02-b`

**사용할 때:** 팀 대전에서 성장 격차가 큰 상대를 만나도 역할이 남게 하고 싶다.

**얻을 결과:** 상성·다중 목표·보상 제한을 활용한 세 대안을 같은 기준으로 비교합니다. 개성, 참여 역할, 역전 조건, 학습 부담, 실패 반례를 열로 두고 조건부 추천을 적습니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion
직업 개성을 유지하면서 성장 격차가 큰 대전의 역할과 역전 가능성을 남길 안을 비교해줘.
가상 입력: 팀 대전에서 성장 격차가 큰 상대를 만나도 역할이 남게 하고 싶다.
확정: 직업 개성 유지. 미정: 상성·다중 목표·보상 제한.
읽을 자료: 원서 1.2절(s02)을 실제 읽고, 전체 관점이 더 필요하면 1장(ch01)을 보충해줘.
산출물: 상성·다중 목표·보상 제한을 활용한 세 대안을 같은 기준으로 비교해줘. 개성, 참여 역할, 역전 조건, 학습 부담, 실패 반례를 열로 두고 조건부 추천을 적어줘.
책의 설명·사례 재구성·새 제안을 구분하고 실제 읽은 자료와 원서 쪽을 적어줘.
미정 정책은 선택지·영향·검증 질문으로 남기고, 자료가 없는 수치를 확정하지 마.
처치(생존) 턴이 같은지를 균형 기준으로 두고 능력치 총합이 비슷한지만 비교하지 말고, 레벨 구간·극단 스탯 분배별 처치 턴, 생존 턴, 공격이 방어를 넘어 실제 피해를 내는지를 검산할 항목으로 둬. 실제 수치가 없으면 필요한 입력과 기호식만 제시하고 계수를 만들지 마.
저자는 ‘실력 차이가 지나치게 벌어지지 않을 때만 효과적’이라는 전제를 제어 균형 전체가 아니라 첫째 관점인 실력 비율(확률·전술로 약자에게 승리 가능성을 두거나 개인을 집단에 편입해 역할을 제한하는 방식)에 붙인다. 특정 플레이어·팀이 압도적일 때의 획득물 제한·유효기간·승패 조건 변경은 별개의 조치로 쓰므로, 상성·다중 목표 대안은 입력의 성장 격차가 첫째 관점의 범위인지 먼저 판정하고 격차의 크기와 원인 자료가 없으면 미확인으로 남겨줘. 보상 제한 대안에는 이 조건을 씌우지 말고 압도적인 플레이어·팀이 입력에 있는지로 따로 판정해줘. 책의 압도 기준(중과금 유저 대비 1대1 20%, 다인 대전 2명)은 사례일 뿐이므로 이 프로젝트의 기준으로 쓰지 마.
```

</details>

**확인할 점:** 세 안의 목표 전투 길이와 직업 개성이 같은 전제인지 봅니다. 처치·생존 턴을 맞추는 밸런스와 격차 속 참여·역전 조건을 남기는 제어 균형을 구분해야 합니다.

**보강 조건 확인:** 레벨별·극단 스탯별 처치 턴, 생존 턴, 실제 피해 가능 여부를 확인합니다. 수치가 없으면 입력 목록·기호식으로 남깁니다. 상성·다중 목표는 성장 격차가 첫째 관점(실력 비율)이 다루는 범위인지, 보상 제한은 압도적인 플레이어·팀이 있는지 따로 판정하며 자료가 없으면 미확인으로 둡니다.

```text
산출물: 극단 조합 / 지배 전략 후보 / 상대 대응 / 참여가 끊기는 조건 / 최소 보완 / 확인할 로그의 반례표를 작성해줘.
변경한 부분과 유지한 부분을 구분하고, 실제 검증을 수행하지 않았다면 검증 계획으로 표시해줘.
앞선 극단 조합별로 레벨 구간, 처치·생존 턴, 실제 피해 가능 여부를 이어받아 검토해줘. 수치가 없는 경우에는 미확인으로 두고 필요한 공격·방어·체력·행동 순서 자료를 적어줘. 같은 처치(생존) 턴을 균형 기준으로 삼고 능력치 총합의 유사성만으로 통과시키지 마.
선행 결과의 성장 격차 범위 판정(상성·다중 목표)과 압도 상황 판정(보상 제한)을 그대로 유지하고, 이미 제어 균형 수단이 들어간 안이면 저자의 사례처럼 새 수단을 더하면 템포를 가볍고 빠르게 유지하기 어려워지는지 먼저 따진 뒤 최소 보완만 제안해줘.
```

</details>

**확인할 점:** 선택하지 않은 다른 안으로 바꾸지 않고, 미정 계수는 계산 조건이나 실험값으로 남겨야 합니다.

**보강 조건 확인:** 선행 결과의 레벨·턴·피해 판정, 성장 격차 범위 판정(상성·다중 목표), 압도 상황 판정(보상 제한)과 미확인 입력을 유지합니다. 능력치 총합이 비슷하다는 이유로 반례를 통과시키지 않고, 균형 기준은 같은 처치(생존) 턴으로 둡니다.

**보강 조건 확인:** 동조의 경로, 공개 판단 시점, 과제 복잡도, 멈추거나 병행해 도울 여력을 구분합니다. 기여 표시·소집단화만으로 협력을 보장하지 않습니다. 이 주의는 스킬 정리이며, 저자는 소집단에서 뛰어난 기여를 모두에게 보이게 하라고도 씁니다. 감독 NPC나 협력 퀘스트로 대응할 때는 즉시 사망하거나 수치상 완수할 수 없는 도전을 제한한 저자의 조건 안에서 검토합니다.

### B. 같은 보상 제시의 순서가 평가·기억에 주는 영향 비교하기 <a id="s04-b"></a>

요청 ID: `s04-b`

**사용할 때:** 동일한 보상안을 다른 순서와 마무리 피드백으로 보여주려 한다.

**얻을 결과:** 제시 대안 / 바뀌는 정보 순서·기준점 / 기대하는 평가·기억 / 효과가 약해질 조건 / 검증 방법의 비교표를 작성합니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion
가격·보상·확률은 같게 두고 제시 순서와 마무리 피드백의 대안을 비교해줘.
가상 입력: 동일한 보상안을 다른 순서와 마무리 피드백으로 보여주려 한다.
확정: 가격·보상·확률 동일. 미정: 프레이밍·기준점·완결 표시.

미정 정책은 선택지·영향·검증 질문으로 남기고, 자료가 없는 수치를 확정하지 마.
제시 순서를 비교할 때 정보 사이 시간과 의견을 묻는 시점을 별도 열로 둬. 미끼 선택지를 사용하는 대안이 있다면 같은 종류의 비교 가능한 타깃·경쟁안·미끼 관계, 가격과 능력·효과가 비례하는 관계인지, 기존 고정관념을 확인해줘. 세 선택지나 순서 변경만으로 효과를 보장하지 마. 프레이밍을 바꾸는 대안이 있다면 저자가 같은 사실도 이익 틀에서는 위험 회피, 손실 틀에서는 위험 추구로 흐른다고 설명하므로(인지 기준점의 변화) 기대하는 평가 열에 틀의 방향을 적고, 손실 틀로 정보 부족을 메우지 마.
```

</details>

**확인할 점:** 제시 방식과 실제 효용의 변경을 섞지 않아야 합니다. 신중한 결제 목표와 사전 설계 경제에 대한 앵커링의 저자 한계도 필요할 때 연결합니다.

**보강 조건 확인:** 정보 간격·의견 측정 시점과 비교 가능한 선택지의 관계(같은 유형, 가격과 효과의 비례)를 확인합니다. 고정관념과 상호작용 적용 한계를 반례로 남깁니다. 프레이밍은 이익 틀과 손실 틀이 서로 다른 위험 태도를 부른다는 방향으로 적고, 손실 틀을 정보 부족의 보완 수단으로 쓰지 않는다는 스킬 정리를 따릅니다.

```text
먼저 게임 속 실패·사망 뒤 다시 시작하는 중단(저자의 첫째 관점)과 게임을 멈추고 실생활로 떠나는 중단(둘째 관점)을 나눠줘. 첫째는 반복 구간이 이미 겪은 긴 구간이라 도전적이지 않은지 확인하되, 저자가 반복을 도전의 일부로 설계하는 경우도 인정하므로 그 경우는 구분해줘. 저장점 대안에는 보스전 앞 저장 포인트와, 처음부터 다시 해야 할 때 플레이어가 직접 세이브를 불러오는 방식(저자가 낫지 않느냐고 묻는 대안)을 넣어 비교해줘. 둘째는 저자의 순서대로 경험 유형(선형이면 중단된 지점에서 즉시 재개, 개방형이면 중단 시간에 따라 유연하게)을 먼저 판정한 뒤 중단 시간으로 판단해줘. 개방형이라면 중단 시간이 짧을 때는 바꾸지 않고 중단된 지점부터 시작하는 안을 기준선으로 두고, 길 때만 이전 경험을 잊었을지 판단해 따로 비교해줘. 현재 입력에 없는 동적 이벤트·난이도 초기화를 이미 있는 기능으로 전제하지 마. 개방형 재개를 별도로 검토하려면 조절 가능한 상태와 고정 콘텐츠의 자료가 더 필요하다고 표시해줘.
```

</details>

**확인할 점:** 실패와 종료를 같은 사건으로 집계하지 않고, 기존 실패 판정과 보상은 유지한 채 복귀 정책을 비교해야 합니다.

**보강 조건 확인:** 게임 속 실패 중단(저장점·반복 길이·복귀 시점)과 실생활로 떠난 중단을 구분하고, 후자는 경험 유형을 먼저, 중단 시간을 그다음에 판단합니다. 이 둘을 하나의 순서로 합치지 않으며, 개방형이라도 중단 시간이 짧으면 바꾸지 않는 것을 기준선으로 둡니다. 입력에 없는 동적 상태를 현재 기능으로 간주하지 않습니다.

## 3.3 기조 <a id="section-08"></a>

**사용할 상황:** 퍼즐과 추격의 속도를 같은 축으로 다루거나, 한 인물이 대기하는 동안 다른 시점으로 긴장을 이어갈 방법을 고를 때 사용합니다.

## 3.4 콘텐츠 설계 <a id="section-09"></a>

**사용할 상황:** 새 지역을 예고해도 매일 같은 행동만 반복되거나, 임무 종료가 종결감과 다음 경험의 이유를 충분히 만들지 못할 때 고릅니다.

**준비할 입력:** 현재 목표, 암시물, 반복 행동, 실제 변화와 다음 목표를 적습니다. 종료 비교에는 동일 임무의 사건·시간, 현재 끝 장면과 보상 표시를 준비합니다.

**읽을 자료:** [s09 — 콘텐츠 설계](../.agents/skills/game-design-for-immersion/references/sections/s09-content-loop.md)와 [원서 3장](../.agents/skills/game-design-for-immersion/chapters/ch03-game-experience.md). 연계할 절은 3.1·4.1·4.3입니다. 원문 탐색 범위는 본문 194–214 / PDF 210–230입니다.

**사용 순서:** A로 기대→행동→변화→다음 목표 사이의 끊긴 연결을 찾습니다. B는 같은 임무의 싱글판과 온라인판에서 끝이 맡을 역할을 비교합니다. 후속은 A의 루프를 목표 하나로 좁힙니다.

- [A. 새 지역의 기대가 반복 루프로 이어지는지 진단하기](#s09-a)
- [B. 같은 임무의 싱글·온라인 종료 피드백 비교하기](#s09-b)

### A. 새 지역의 기대가 반복 루프로 이어지는지 진단하기 <a id="s09-a"></a>

요청 ID: `s09-a`

**사용할 때:** 새 지역을 예고하지만 매일 같은 수치 보상과 행동만 반복한다.

**얻을 결과:** 목표·암시물 / 현재 행동 / 실제 변화 / 성취·만족 / 다음 목표 / 끊긴 연결의 루프표와 최소 변경안을 작성합니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion
새 지역의 기대가 매일의 행동·변화·다음 목표로 이어지는지 진단해줘.
가상 입력: 새 지역을 예고하지만 매일 같은 수치 보상과 행동만 반복한다.
확정: 지역 목표·보상 총량 유지. 미정: 암시물·새 전략·목표 단계.
읽을 자료: 원서 3.4절(s09)을 실제 읽고, 전체 관점이 더 필요하면 3장(ch03)을 보충해줘.
산출물: 목표·암시물 / 현재 행동 / 실제 변화 / 성취·만족 / 다음 목표 / 끊긴 연결의 루프표와 최소 변경안을 작성해줘.
책의 설명·사례 재구성·새 제안을 구분하고 실제 읽은 자료와 원서 쪽을 적어줘.
미정 정책은 선택지·영향·검증 질문으로 남기고, 자료가 없는 수치를 확정하지 마.
지역 목표를 유지한 채, 진입 즉시 충분한 플레이가 있는지와 기획자의 확신 근거를 함께 확인하고 선행 시연이 더 필요한지를 비교해줘. 두 조건 중 하나라도 확인되지 않으면 시연 생략을 확정하지 마. 수치 성장이 채우는 기대와 새 게임플레이가 있어야 채워지는 기대를 나누고, 새 행동·전략을 성장 곡선에 붙이는 안은 레벨이 아니라 캐릭터 외부의 성장 축(펫·특성·장비 등)에 두었는지 확인해줘. 새 사회적 루프를 대안에 포함했다면 실시간·비동기·책의 반실시간 비동기 구분에서 교류감·즉시성·구현 제약을 적고, 온라인 방식은 미정으로 남겨줘. 새 지역의 암시물은 저자가 소유물이나 표식이어야 하고 인터페이스의 특정 입구가 되어서는 안 된다고 쓰므로, 지역 예고를 배너나 선택 화면 같은 UI 입구에만 두지 않았는지 확인해줘. 목표 단계는 목표가 없거나 너무 멀어 닿을 수 없으면 동기를 끌어내기 어렵다는 저자의 서술에 비춰, 단계 보상이 큰 목표를 작은 목표로 나누는지 적어줘.
```

</details>

**확인할 점:** 지역 목표와 보상 총량을 유지하면서 새 행동·전략을 연결해야 합니다. 일일 체크리스트 자체를 루프의 충분한 설명으로 쓰지 않습니다.

**보강 조건 확인:** 진입 즉시 플레이가 충분한지와 기획자의 확신 근거를 모두 확인한 뒤 선행 시연의 필요성을 비교합니다. 새 행동을 성장 곡선에 붙이는 안은 레벨이 아니라 캐릭터 외부의 성장 축에 두었는지 봅니다. 사회적 루프를 선택했을 때만 온라인 방식의 조건을 추가합니다. 암시물이 소유물·표식인지(UI 입구는 암시물로 보지 않음), 목표가 닿을 수 있는 거리에 있고 단계 보상이 작은 목표로 이어지는지도 확인합니다.

### B. 같은 임무의 싱글·온라인 종료 피드백 비교하기 <a id="s09-b"></a>

요청 ID: `s09-b`

**사용할 때:** 동일한 짧은 임무를 싱글판과 협력 온라인판에 넣으려 한다.

**얻을 결과:** 종료 상황 / 종결감 / 다음 경험의 이유 / 보상 표시 / 피드백 초안 / 강제 재참여 위험의 비교표를 작성합니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion

가상 입력: 동일한 짧은 임무를 싱글판과 협력 온라인판에 넣으려 한다.
확정: 임무 사건·시간 유지. 미정: 종결감·다음 목표 노출.
읽을 자료: 원서 3.4절(s09)을 실제 읽고, 전체 관점이 더 필요하면 3장(ch03)을 보충해줘.
산출물: 종료 상황 / 종결감 / 다음 경험의 이유 / 보상 표시 / 피드백 초안 / 강제 재참여 위험의 비교표를 작성해줘.
책의 설명·사례 재구성·새 제안을 구분하고 실제 읽은 자료와 원서 쪽을 적어줘.
미정 정책은 선택지·영향·검증 질문으로 남기고, 자료가 없는 수치를 확정하지 마.
협력 온라인판의 상호작용 방식은 아직 정해졌다고 가정하지 마. 실시간·비동기·책의 반실시간 비동기 대안을 상대에게 미치는 변화, 교류감, 즉시성, 구현 제약으로 비교하되 책의 구분명을 네트워크 구현 보증으로 쓰지 마. 저자는 종결감을 싱글플레이어 게임이 반드시 제공해야 하는 느낌이지만 진짜 엔딩과는 다르다고 쓰고 온라인 게임은 종결감을 원하지 않아도 하나 이상의 최종 목표가 필요하다고 쓰므로, 두 판을 이 구분에 맞춰 종결감 열에 적어줘. 다음 경험의 이유로는 저자가 든 방법(결과를 알 수 없게 끊어 다음 날 잇는 퀘스트, 시간성 있는 계기, 자원이 바닥나면 내일까지 기다리게 하기)을 구분하고, 마지막 방식은 설계 수준이 매우 높아야 한다는 저자의 단서가 있으므로 강제 재참여 위험 열에서 따로 판정해줘.
```

</details>

**확인할 점:** 임무 사건과 시간이 같은 조건인지 확인합니다. 종결과 다음 목표 노출을 비교하되 실제 유지율 효과를 확정하지 않습니다.

**보강 조건 확인:** 온라인판이라는 이유로 실시간 방식을 확정하지 않습니다. 교류감·즉시성·구현 제약을 비교하며 책의 구분명을 구현 보증으로 쓰지 않습니다. 싱글판의 종결감과 온라인판의 최종 목표를 구분하고, 자원 소진 뒤 대기 방식은 설계 수준이 매우 높아야 한다는 단서와 함께 봅니다.

**이어서 할 일:** 남긴 목표 / 목표의 의미 / 클릭을 대체할 맥락 있는 행동 / 즉시 변화 / 다음 참여 이유 / 검토 기준의 루프 수정표를 만들어 기존 결과를 보완합니다. 새 대화에는 결과 발췌와 확정·미정 목록, 사용한 근거 위치를 함께 제공합니다.

<summary><strong>프롬프트 펼치기</strong></summary>

```text
그대로 남길 미정 사항: [아직 결정하지 않은 정책·수치 목록]
방금 초안에서 다음 목표 하나만 남겨줘. 클릭 행동을 바꾸는 대안을 최소선(특정 동작)·권장(일련의 조작)·선택(제스처나 상징 행동)으로 나눠 적고 검토 기준을 붙여줘.
산출물: 남긴 목표 / 목표의 의미 / 클릭을 대체할 맥락 있는 행동 / 즉시 변화 / 다음 참여 이유 / 검토 기준의 루프 수정표를 작성해줘.

선행 결과의 현재 플레이 충분성·기획자 확신 근거·시연 필요성·성장 곡선에 붙인 새 행동의 위치·사회적 상호작용 방식 판정을 유지해줘. 다음 목표를 좁힌다는 이유로 미정 온라인 방식이나 새 시스템을 확정하지 마.
```

**보강 조건 확인:** 플레이 충분성·기획자 확신 근거·시연 필요성·새 행동의 성장 축 위치·상호작용 방식의 선행 판정을 유지합니다. 목표를 좁히면서 미정 시스템을 확정하지 않습니다.

## 4.2 가치체계 구축 <a id="section-12"></a>

**사용할 상황:** 희귀한 보상을 지급해도 사용·전시가 없거나, 같은 효용을 여러 경로로 얻도록 하면서 경로의 가치를 비교하려는 상황에 맞습니다.

### A. 완전·반·불가 유통의 경제·교류 비용 비교하기 <a id="s14-a"></a>

요청 ID: `s14-a`

**사용할 때:** 제작 재료와 장비의 거래 정책을 결정하려 한다.

**얻을 결과:** 유통안 / 공급·소비 / 가치 / 교류 / 부캐 이전 범위 / 사기·작업장 가능성 / 운영 비용의 비교표를 작성합니다.

```text
귀속 판단은 저자의 두 기준(아이템의 가치, 모든 플레이어가 직접 완료하길 원하는지)과 스킬 정리가 더한 항목(부캐 이전 피해, 거래의 사회적 이득)을 나눠 적어줘. 완전 유통의 필요는 전제 조건이고, 저자는 고정 팀원·일반 친구 두 관계층이 설계되면 유통이 그 범위까지만 도달해도 충분하다고 쓴다. 유통이 제한될수록 결제자가 상대적으로 불리해질 수 있다는 서술(유통 불가에 한정하지 않음)과, 결제자는 그렇게 인식하지 않고 지불 후 경험으로 가치를 판단한다는 저자의 결론도 함께 적어줘. 고정 팀원·일반 친구 두 관계층의 설명은 <월드 오브 워크래프트> 사례와 여가 시간이 적은 직장인·중년층 플레이어라는 전제 위에 있고 조사 근거는 밝히지 않으므로, 이 프로젝트 대상이 그 전제에 맞는지 입력으로 판정하고 자료가 없으면 미확인으로 남겨줘.
```

</details>

**확인할 점:** 외형만 유료와 동일 장비 성능을 유지합니다. 거래 불가와 완전 귀속의 차이를 지우거나 미정 거래 규칙을 확정하지 않습니다.

**보강 조건 확인:** 직접 거래·귀속·시스템 재유통을 따로 확인합니다. 시스템 재판매가 있으면 책의 유통 불가로 분류하지 않습니다. 귀속은 저자의 두 기준과 스킬 정리 항목을 구분하고, 결제자 불리 서술은 저자의 반대 결론과 함께 봅니다. 두 관계층의 설명은 〈월드 오브 워크래프트〉와 여가 시간이 적은 직장인·중년층 전제로 한정해 읽습니다.

### 후속. 선택한 유통·호혜안의 이전·사기·공급 반례 점검하기 <a id="s14-followup"></a>

**사용할 때:** 책의 소·중·고과금 분류를 현재 기획 회의에서 설명하려 한다.

**얻을 결과:** 모형의 관점 / 가져올 내용 / 제외할 가정 / 확정 정책 충돌 / 외형·전시 대안 / 추가 관측 자료의 검토표를 작성합니다.

## 4.6 유료 콘텐츠 <a id="section-16"></a>

**사용할 상황:** 부족한 재료와 외형 전시 욕구를 같은 구매 동기로 취급하거나, 책의 결제 금액표를 현행 상품에 옮기기 전에 범위를 확인할 때 고릅니다.

```text
책의 설명·사례 재구성·새 제안을 구분하고 실제 읽은 자료와 원서 쪽을 적어줘.
미정 정책은 선택지·영향·검증 질문으로 남기고, 자료가 없는 수치를 확정하지 마.
```

</details>

**확인할 점:** 실제 사업 방향·가격·서버 정책은 미정으로 남기고, 모델 이름만으로 현재 서비스의 정답을 추천하지 않습니다.

**보강 조건 확인:** AFK·서버 통합은 자원 독점형에 대한 서술입니다. 소·중·고과금 유저형은 그 문제로 잃은 유저층을 되찾는 방법이며, 녹색은 PVE로 대부분의 자원을 얻게 하고 추가 유료 아이템 가격을 높여 추가 결제를 억제하는 모델입니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>


### 목표 없는 짧은 경험에서 템포·선행 시연 대안 비교하기 <a id="common-08"></a>

요청 ID: `common-08`

**사용할 때:** 명시적 목표 없이 즉시 조작하는 경험에서 기대와 집중을 검토한다.

**얻을 결과:** 즉시 가능한 행동 / 현재 이해의 공백 / 템포 대안 / 시연 필요·생략 조건 / 집중·피로 반례 / 종료 피드백 / 검증 질문을 받습니다. 조건 판정·판단 근거·미확인 자료도 함께 받습니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion
가상 입력: 색과 소리를 자유롭게 만지는 2분 샌드박스이며 진입 즉시 여러 조작을 할 수 있다.
확정: 장기 퀘스트 없음·즉시 자유 조작 유지. 미정: 입력 템포·선행 시연·마무리 피드백.
읽을 자료: s09의 목표 없는 경험과 시연의 예외, 필요하면 s08의 기조를 읽어줘.
빠른 템포는 저자가 목표 부재의 부작용을 상쇄할 유일한 방법으로 든 것이므로 그 조건과, 템포와 무관하게 목표가 있을 때 집중·기대가 더 쉽다는 한계, 반대로 혼란·피로를 키울 반례를 비교해줘. 선행 시연 생략은 기획자가 게임에 확신이 충분하고 진입 순간부터 충분한 게임플레이를 줄 수 있다는 두 조건이 함께일 때의 선택지이므로, 두 조건을 따로 판정한 뒤 생략한 안도 비교해줘. 템포만으로 몰입을 보장하지 말고, 장기 목표·퀘스트를 확정 정책과 충돌하게 추가하지 마.
산출물: 즉시 가능한 행동 / 현재 이해의 공백 / 템포 대안 / 시연 필요·생략 조건 / 집중·피로 반례 / 종료 피드백 / 검증 질문을 작성하고, 적용 조건의 성립·불성립·미확인·해당 없음 판정 / 판단 근거(원서 쪽·입력·관측) / 다음에 확인할 자료를 별도 열로 적어줘.
책의 설명·사례 재구성·새 제안을 구분하고 원서 쪽과 실제 읽은 자료를 적어줘.
미정 사항은 선택지·영향·검증 질문으로 남겨줘.
```

</details>

**확인할 점:** 목표 없음의 예외를 모든 게임의 권장안으로 확대하지 않고, 플레이 충분성에 따라 시연을 선택하는지 확인합니다. 시연 생략의 두 조건(기획자의 확신, 진입 순간의 충분한 게임플레이) 판정이 근거와 함께 남았는지 봅니다.

### 후속. 새 목표를 강제하지 않고 시연 생략안의 집중·이해 확인하기 <a id="common-08-followup"></a>

요청 ID: `common-08-followup`

**이어받을 결과:** 선택한 템포·시연 대안, 즉시 가능한 행동과 이해의 공백, 유지할 자유 조작·장기 퀘스트 없음 조건을 전달합니다. 조건 판정·근거·미확인 항목도 함께 전달합니다.

**보완할 범위:** 현재 자유 조작을 유지하며 시연 생략·추가의 비용을 비교합니다. 새 목표·시간 규격은 확정하지 않습니다.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion
선행 요청: common-08. [선택한 안을 입력]
이어받을 결과: [선택한 템포·시연 대안, 즉시 가능한 행동과 이해의 공백, 유지할 자유 조작·장기 퀘스트 없음 조건]
이어받을 조건·예외: [선행 결과의 성립·불성립·미확인·해당 없음 판정, 각 판정의 원서 쪽·입력·관측 근거, 다음에 확인할 자료]
유지할 확정 정책: [선행 요청의 확정 목록]
그대로 남길 미정 사항: [선행 요청의 미정 목록]
선택한 안에서 현재 조작과 피드백만으로 이해할 수 있는지 확인해줘. 시연을 생략했을 때 조작 발견이 어려워지는 반례와, 넣었을 때 자유 조작을 지연하는 반례를 비교해줘. 새 목표나 시간을 필수 규격으로 만들지 말고 미정 시연·종료 피드백은 선택지로 남겨줘.
산출물: 선택안 / 발견하기 어려운 행동 / 현재 피드백 / 시연 생략·추가의 비용 / 유지할 확정 조건 / 미정 대안 / 관찰 질문의 비교표를 작성하고, 선행 조건 판정의 유지·변경 여부와 그 근거를 적어줘.
변경한 부분과 유지한 부분을 구분하고, 실제로 검증하지 않은 내용은 검증 계획으로 표시해줘.
```

</details>

**확인할 점:** 목표 없음의 예외를 모든 게임의 권장안으로 확대하지 않고, 플레이 충분성에 따라 시연을 선택하는지 확인합니다. 선행 결과의 조건 판정이 후속에서도 유지되는지 봅니다.

### 3분 협력 액션을 목표 경험부터 보상·검증까지 설계하기 <a id="chain-01"></a>

요청 ID: `chain-01`

새 스테이지의 행동·협력·곡선·보상을 하나의 조건으로 연결합니다.

**단계별로 넘길 결과:** 목표 경험과 확정·미정 목록 → 역할·행동표 → 경험 타임라인 → 보상 연결표 → 플레이테스트 계획.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion 3분 협력 액션 스테이지를 새로 설계해줘.
가상 목표: 서로의 엄호가 마지막 돌파를 만들었다고 느끼기.
확정: 전투력 판매 없음·보상 총량 유지. 미정: 역할·재시도·회복 시간.
1장 조작/선택 → 2장 공통 경험 → 3장 곡선/기조 → 4장 보상 순으로 필요한 자료를 읽어줘.
산출물: 목표문, 행동/상호 기여 표, 경험 타임라인, 보상 연결, 미정 선택지, 플레이테스트 계획.
책의 설명과 새 적용안을 구분해줘.
단계마다 사용할 자료, 입력으로 받을 이전 표, 새 산출물, 다음 단계에 넘길 확정·미정 목록을 적어줘.
```

</details>

**확인할 점:** 앞 단계의 목표와 정책을 다음 표에 그대로 넘깁니다. 역할·재시도·회복 시간을 선택하기 전에는 대안별 결과로 남깁니다.

### 6개 성장 경로의 체감 문제를 수요·보상·루프로 개선하기 <a id="chain-02"></a>

요청 ID: `chain-02`

성장 수치는 오르지만 새 행동과 콘텐츠가 열리지 않는 문제를 좁힙니다.

**단계별로 넘길 결과:** 원인 가설·자료 요청 → 합계·증가량·해금 검토표 → 수요·난관 대응 → 보상·루프 변경안 → 재검산·플레이테스트 기준.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion 성장 시스템 6개가 있지만 진전감이 약한 문제를 진단해줘.
가상 자료: 매일 수치는 오르지만 새 행동과 지역은 거의 열리지 않는다.
확정: 총 능력 목표·외형만 유료 유지. 미정: 상승 시작점·주기·해금 시점.
4.1 합계/증가량 → 4.2 수요 → 4.3 보상 → 3.4 루프의 자료를 읽어 연결해줘.
4.1 단계에서는 책의 ‘성장 곡선’이 수치 성장만 가리킨다는 점에 따라 수치 상승(작은 파동)과 새 능력·챕터 해금(큰 파동)을 나눠 어느 쪽이 비어 있는지 판정해줘. 게임이 능력 성장 비중형인지 수치 성장 비중형인지도 입력으로 판정하고 다음 단계에 넘겨줘. 성장선을 더 쪼개는 안은 콘텐츠·과금 목적이면 불필요하다는 저자의 설명과 한 곡선 안의 차별화를 대안으로 비교하되 외형만 유료 조건에 맞는 것만 남겨줘. 4.3 단계에서는 보상이 해금하는 콘텐츠와 바꾸는 전투 경험을 먼저 적고 성장 감각의 리듬은 4.1 표에서 가져와줘.
산출물: 원인 가설, 데이터 요청, 새 행동과 난관 대응, 최소 변경안, 검산/플레이테스트 기준.
책의 설명과 새 적용안을 구분해줘.
단계마다 사용할 자료, 입력으로 받을 이전 표, 새 산출물, 다음 단계에 넘길 확정·미정 목록을 적어줘.
```

</details>

**확인할 점:** 확인된 값과 가설을 단계마다 구분합니다. 자료가 없으면 계산 결과 대신 필요한 입력을 넘기고, 총 능력·외형 유료 정책을 유지합니다.

**보강 조건 확인:** 큰 파동·작은 파동의 판정과 곡선 분할 여부를 판단한 이유, 능력·수치 비중형 판정을 다음 단계 입력에 함께 넘깁니다.

### 장비 귀속을 유지한 재료 거래 변경의 경제·교류 영향 검증하기 <a id="chain-03"></a>

요청 ID: `chain-03`

거래 범위의 일부만 바꿔 공급·가치·협력에 미치는 영향을 검토합니다.

**단계별로 넘길 결과:** 기존 정책·변경 대상 → 유통 경계표 → 가치·공급 영향표 → 상호 기여 검토 → 확정 필수 결과·미정 정책별 반례.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion 기존 유통 불가안에서 일부 제작 재료만 거래하는 변경안을 검토해줘.
자료: [기존 정책과 답변을 제공]. 확정: 장비 완전 귀속·외형만 유료.
미정: 거래 재료 범위·수수료·부캐 이전·공급량.
4.4 유통 → 4.2 가치 → 4.8 공급/소비 → 2.3 교류의 자료를 읽어줘.
산출물: 변경 경계, 가치/공급/관계 영향, 확정 필수 결과, 미정 정책별 반례와 검증 계획.
검증 계획을 실제 수행 결과라고 쓰지 마.
책의 설명과 새 적용안을 구분해줘.
단계마다 사용할 자료, 입력으로 받을 이전 표, 새 산출물, 다음 단계에 넘길 확정·미정 목록을 적어줘.
첫 단계에서 직접 거래·귀속·시스템 재유통의 현 상태를 별도로 확인해줘. 호혜가 포함되면 신규와 숙련자 각각의 부족 자원과 상호 이득을 다음 단계에 넘겨줘. 이후 단계에서도 외형만 유료를 외형 가격·할인 금지로 확대하지 마. 재료 거래로 가치 하락이 우려되면 저자가 든 인플레이션 대응(매우 긴 성장 곡선, 확률 강화, 소비와 획득을 모두 적게 두고 핵심 성장을 귀속 장비로 결정) 중 확정된 완전 귀속과 맞는 것과 입력에 없는 것을 나눠 적어줘.
```

</details>

**확인할 점:** 장비 완전 귀속과 외형만 유료 조건을 모든 단계에 넘깁니다. 수수료·부캐 이전·공급량은 미정으로 유지하며 계획과 실행 결과를 구분합니다.

**보강 조건 확인:** 각 단계에 유통 경계, 양쪽 필요, 확정·미정 정책을 전달합니다. 장비 귀속이나 외형 유료 조건의 적용 범위를 확대하지 않습니다. 재료 거래의 가치 하락 대응은 확정된 완전 귀속과 맞는지 따로 적습니다.

## 공통 산출물 검수 <a id="review-criteria"></a>

| 확인할 항목 | 답변에 남아 있어야 할 것 | 다시 요청할 신호 |
|---|---|---|
| 실제 근거 | 읽은 파일, 원서 절·쪽, 책 설명과 새 제안의 구분 | 색인만 읽고 세부 조건 단정 |
| 인용 쪽 | 책의 서술에는 자료의 문장 단위 쪽을 붙이고, 스킬 정리·새 제안은 책의 서술과 구분 | ‘목차 탐색 범위’ 같은 절 전체 쪽 범위를 근거로 인용, 스킬 정리를 저자 서술로 소개 |
| 조건·예외 | 적용 조건의 성립·불성립·미확인·해당 없음 판정, 판단 근거(원서 쪽·입력·관측), 다음에 확인할 자료 | 조건 이름만 나열하고 입력과 연결하지 않음 |
| 목표와 행동 | 목표 경험을 만드는 선택·행동·피드백 | 재미·긴장·보상 증가만 반복 |
| 정책과 가정 | 유지한 확정 조건, 미정 대안, 새 제안의 가정 | 선택 전 가격·주기·역할 확정 |
| 수치 | 단위·시작점·누적·비중·검산 또는 입력 공백 | 주기와 첫 상승, 상승 횟수와 능력값 혼동 |
| 변경 경계 | 바꾼 항목과 유지한 항목, 연결된 영향 | 목표·보상·정책을 동시에 바꿔 비교 |
| 검증 상태 | 수행한 검산의 근거 또는 미실행 검증 계획 | 계획한 QA·플레이테스트를 완료로 표현 |

**후속으로 넘길 최소 묶음**은 선행 요청 ID, 선택한 안·표, 확정 정책, 미정 목록, 적용 조건·예외의 판정, 근거 위치, 다음에 바꿀 항목입니다. 같은 대화여도 어떤 안을 골랐는지 지정하고, 새 대화에는 해당 결과 발췌를 붙입니다.

원문 표의 불명확한 기호·VIP 행 라벨은 추정 복원하지 않습니다. 심리 효과·리텐션·매출은 관측 근거 없이 확정하지 않습니다. 쪽 인용이 절 전체 범위로 나오면 [문제 해결](troubleshooting.md#citations)의 요청으로 다시 받습니다. 더 자세한 기준은 [검수와 테스트](validation.md), 빠른 초안 확인은 [판단표](../.agents/skills/game-design-for-immersion/cheatsheet.md), 원문 범위는 [목차 대응](../.agents/skills/game-design-for-immersion/references/coverage.md)을 사용합니다.

이 문서의 예시를 보완하고 링크·조건을 검토한 것과 실제 게임·호스트에서 예시를 수행한 것은 다릅니다. 문서가 바뀌기 전의 실행 기록을 현재 가이드 전체의 시험 결과로 재사용하지 않습니다.
