실제 기획 문제에 맞는 예시를 골라 **필요한 자료를 읽고 → 결과를 비교·선택하고 → 후속 요청으로 좁혀 가는** 가이드입니다. 원서 4장의 관점과 상세 18절을 연결하며, **절별 예시 36개, 절별 후속 요청 18개, 공통 예시 8개와 공통 후속 요청 4개, 연계 시나리오 3개**를 제공합니다.

> **책의 설명과 이 가이드의 적용 예시를 구분합니다.** 가상 프로젝트의 상황·수치는 새 응용 예시이며 저자의 공식 절차나 실제 서비스의 확정 사양이 아닙니다. 표 4.1·4.10·4.11을 조회하는 예시는 원문 사례를 확인하는 작업입니다. 그 사례값을 프로젝트 기본값으로 옮기지 않습니다.

## 요청문 작성과 자료 선택

Codex에서는 `$game-design-for-immersion`, Claude Code에서는 `/game-design-for-immersion`으로 시작합니다. Antigravity에서는 스킬 이름을 포함한 자연어 요청을 사용할 수 있으며, slash 호출은 설치 버전의 지원 여부를 확인합니다. 원서 장은 `ch01`–`ch04`, 상세 자료는 `s01`–`s18`입니다.

특정 기법·조건은 상세 절에서 시작하고, 큰 설계 관점이 필요할 때 장 자료를 보충합니다. 원문 절 번호·용어·수치로 찾을 때는 [참조 색인](../.agents/skills/game-design-for-immersion/references/index.md), [전략 절별 바로가기](../.agents/skills/game-design-for-immersion/references/sections/s02-cold-strategy.md#strategy-locations), [심리 기법 바로가기](../.agents/skills/game-design-for-immersion/references/sections/s04-psychology.md#crowd)를 이용합니다.

각 예시의 **가상 입력을 실제 프로젝트 정보로 바꾸고**, 유지할 확정 정책과 아직 선택하지 않은 정책을 나눕니다. 목표 시간·보상·현재값이 없다면 필요한 자료 목록이나 기호식부터 받습니다.

```text
$game-design-for-immersion [현재 문제]를 [진단/설계/비교/검토]해줘.
맥락: [장르·대상 플레이어·콘텐츠 구간·현재 자료]
확정: [유지할 조건] / 미정: [아직 정하지 않은 변수]
읽을 자료: [관련 원서 절과 ch##/s##]
산출물: [결정에 필요한 표·초안·검토 결과와 열]
책의 설명과 새 제안을 구분하고, 읽은 자료·원서 쪽을 적어줘.
자료가 없는 수치는 미정으로 남기고 다음에 필요한 입력을 알려줘.
```

**정책을 읽는 기준:** 판매 대상·플레이 효과와 가격·혜택 조건을 나눕니다. 예를 들어 외형만 유료라는 정책은 성능·진행 우위 판매를 배제하지만, 아직 미정인 외형 가격·전시 등급·외형 전용 할인까지 자동 금지하지는 않습니다.

**결과를 이어갈 때:** 같은 대화에서는 선행 요청 ID와 선택한 안을 지정합니다. 새 대화에서는 **선택한 표·초안, 유지할 확정 정책, 미정 목록, 적용 조건·예외의 판정과 근거 위치**를 함께 제공합니다. “방금 결과를 보완해줘”만으로는 어떤 안을 고른 것인지 재현하기 어렵습니다.

## 보강한 조건·예외로 예시 찾기 <a id="refined-conditions"></a>

조건은 읽었다는 표시보다 **성립 여부·판단 근거·해당 없는 범위**로 산출물에 남기는 것이 중요합니다. 후속 요청에는 이 판정과 미확인 항목을 함께 전달합니다.

| 확인할 조건·예외 | 예시에서 실제로 할 판단 | 예시·후속 |
|---|---|---|
| 쾌감의 원천·극단 스탯 | 캐릭터/플레이어 경험과 실제 효율을 구분하고 턴·피해를 검산 | [보스 역산](#s01-b), [균형 반례](#s02-followup) |
| 비전투 전략·단기 미션 | 핵심 루프의 선택과 템포 비용을 비교 | [경영 예시](#common-05) → [미션 후속](#common-05-followup) |
| 분노·심리 용어·요청 순서 | 사건 유형의 성립 조건과 책/일반 용어의 범위를 분리 | [심리 조건 학습](#common-06) → [조건 변경 후속](#common-06-followup) |
| 동조·협력·제시 순서 | 공개 판단 시점·도움 여력·비교 관계·정보 간격을 확인 | [협력 진단](#s04-a), [제시 비교](#s04-b) → [반례 후속](#s04-followup) |
| 장기 복귀·메인 복귀 표지 | 조절 가능한 상태와 고정 콘텐츠를 분리하고 표지 개수는 강제하지 않음 | [고정 퀘스트 복귀](#common-07) → [배너 후속](#common-07-followup), [분기 후속](#s10-followup) |

| 저효율·영구 보상 | 확실성·영구성·대체 가능성을 시간 효율과 함께 판단 | [획득 경로](#s12-b) → [가치 후속](#s12-followup) |
| 귀속·시스템 재유통·호혜 | 실제 유통 경로와 양쪽 부족 자원이 교차하는지 확인 | [유통 비교](#s14-a), [호혜 설계](#s14-b) → [유통·호혜 후속](#s14-followup) |
| 상품 효과·가격·소비 집단 | 확정 정책의 축을 확대하지 않고 구매 한도·진행·일일 시간·수요를 비교 | [과금 경계](#s15-b), [등급 사례](#s16-b) → [상품 후속](#s16-followup) |

<summary><strong>프롬프트 펼치기</strong></summary>


**확인할 점:** 없는 동적 상태·워밍업 구간을 있는 것처럼 전제하지 않고, 하나의 표지로도 조건부 개선이 가능한지 확인합니다. 선행 결과의 조건 판정이 후속에서도 유지되는지 봅니다.


### 목표 없는 짧은 경험에서 템포·선행 시연 대안 비교하기 <a id="common-08"></a>

</details>

**확인할 점:** 목표 없음의 예외를 모든 게임의 권장안으로 확대하지 않고, 플레이 충분성에 따라 시연을 선택하는지 확인합니다.

### 3분 협력 액션을 목표 경험부터 보상·검증까지 설계하기 <a id="chain-01"></a>

요청 ID: `chain-01`

새 스테이지의 행동·협력·곡선·보상을 하나의 조건으로 연결합니다.

**단계별로 넘길 결과:** 목표 경험과 확정·미정 목록 → 역할·행동표 → 경험 타임라인 → 보상 연결표 → 플레이테스트 계획.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion 3분 협력 액션 스테이지를 새로 설계해줘.
가상 목표: 서로의 엄호가 마지막 돌파를 만들었다고 느끼기.
확정: 전투력 판매 없음·보상 총량 유지. 미정: 역할·재시도·회복 시간.
1장 조작/선택 → 2장 공통 경험 → 3장 곡선/기조 → 4장 보상 순으로 필요한 자료를 읽어줘.
산출물: 목표문, 행동/상호 기여 표, 경험 타임라인, 보상 연결, 미정 선택지, 플레이테스트 계획.
책의 설명과 새 적용안을 구분해줘.
단계마다 사용할 자료, 입력으로 받을 이전 표, 새 산출물, 다음 단계에 넘길 확정·미정 목록을 적어줘.
```

</details>

**확인할 점:** 앞 단계의 목표와 정책을 다음 표에 그대로 넘깁니다. 역할·재시도·회복 시간을 선택하기 전에는 대안별 결과로 남깁니다.

### 6개 성장 경로의 체감 문제를 수요·보상·루프로 개선하기 <a id="chain-02"></a>

요청 ID: `chain-02`

성장 수치는 오르지만 새 행동과 콘텐츠가 열리지 않는 문제를 좁힙니다.

**단계별로 넘길 결과:** 원인 가설·자료 요청 → 합계·증가량·해금 검토표 → 수요·난관 대응 → 보상·루프 변경안 → 재검산·플레이테스트 기준.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion 성장 시스템 6개가 있지만 진전감이 약한 문제를 진단해줘.
가상 자료: 매일 수치는 오르지만 새 행동과 지역은 거의 열리지 않는다.
확정: 총 능력 목표·외형만 유료 유지. 미정: 상승 시작점·주기·해금 시점.
4.1 합계/증가량 → 4.2 수요 → 4.3 보상 → 3.4 루프의 자료를 읽어 연결해줘.
산출물: 원인 가설, 데이터 요청, 새 행동과 난관 대응, 최소 변경안, 검산/플레이테스트 기준.
책의 설명과 새 적용안을 구분해줘.
단계마다 사용할 자료, 입력으로 받을 이전 표, 새 산출물, 다음 단계에 넘길 확정·미정 목록을 적어줘.
```

</details>

**확인할 점:** 확인된 값과 가설을 단계마다 구분합니다. 자료가 없으면 계산 결과 대신 필요한 입력을 넘기고, 총 능력·외형 유료 정책을 유지합니다.

### 장비 귀속을 유지한 재료 거래 변경의 경제·교류 영향 검증하기 <a id="chain-03"></a>

요청 ID: `chain-03`

거래 범위의 일부만 바꿔 공급·가치·협력에 미치는 영향을 검토합니다.

**단계별로 넘길 결과:** 기존 정책·변경 대상 → 유통 경계표 → 가치·공급 영향표 → 상호 기여 검토 → 확정 필수 결과·미정 정책별 반례.

<details>
<summary><strong>프롬프트 펼치기</strong></summary>

```text
$game-design-for-immersion 기존 유통 불가안에서 일부 제작 재료만 거래하는 변경안을 검토해줘.
자료: [기존 정책과 답변을 제공]. 확정: 장비 완전 귀속·외형만 유료.
미정: 거래 재료 범위·수수료·부캐 이전·공급량.
4.4 유통 → 4.2 가치 → 4.8 공급/소비 → 2.3 교류의 자료를 읽어줘.
산출물: 변경 경계, 가치/공급/관계 영향, 확정 필수 결과, 미정 정책별 반례와 검증 계획.
검증 계획을 실제 수행 결과라고 쓰지 마.
책의 설명과 새 적용안을 구분해줘.
단계마다 사용할 자료, 입력으로 받을 이전 표, 새 산출물, 다음 단계에 넘길 확정·미정 목록을 적어줘.
첫 단계에서 직접 거래·귀속·시스템 재유통의 현 상태를 별도로 확인해줘. 호혜가 포함되면 신규와 숙련자 각각의 부족 자원과 상호 이득을 다음 단계에 넘겨줘. 이후 단계에서도 외형만 유료를 외형 가격·할인 금지로 확대하지 마.
```

</details>

**확인할 점:** 장비 완전 귀속과 외형만 유료 조건을 모든 단계에 넘깁니다. 수수료·부캐 이전·공급량은 미정으로 유지하며 계획과 실행 결과를 구분합니다.


---

**보강 조건 확인:** 각 단계에 유통 경계, 양쪽 필요, 확정·미정 정책을 전달합니다. 장비 귀속이나 외형 유료 조건의 적용 범위를 확대하지 않습니다.

| 수치 | 단위·시작점·누적·비중·검산 또는 입력 공백 | 주기와 첫 상승, 상승 횟수와 능력값 혼동 |
| 변경 경계 | 바꾼 항목과 유지한 항목, 연결된 영향 | 목표·보상·정책을 동시에 바꿔 비교 |
| 검증 상태 | 수행한 검산의 근거 또는 미실행 검증 계획 | 계획한 QA·플레이테스트를 완료로 표현 |

**후속으로 넘길 최소 묶음**은 선행 요청 ID, 선택한 안·표, 확정 정책, 미정 목록, 근거 위치, 다음에 바꿀 항목입니다. 같은 대화여도 어떤 안을 골랐는지 지정하고, 새 대화에는 해당 결과 발췌를 붙입니다.

원문 표의 불명확한 기호·VIP 행 라벨은 추정 복원하지 않습니다. 심리 효과·리텐션·매출은 관측 근거 없이 확정하지 않습니다. 더 자세한 기준은 [검수와 테스트](validation.md), 빠른 초안 확인은 [판단표](../.agents/skills/game-design-for-immersion/cheatsheet.md), 원문 범위는 [목차 대응](../.agents/skills/game-design-for-immersion/references/coverage.md)을 사용합니다.

이 문서의 예시를 보완하고 링크·조건을 검토한 것과 실제 게임·호스트에서 예시를 수행한 것은 다릅니다. 문서가 바뀌기 전의 실행 기록을 현재 가이드 전체의 시험 결과로 재사용하지 않습니다.
